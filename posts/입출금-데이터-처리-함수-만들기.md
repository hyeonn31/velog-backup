## 1. 라이브러리와 상수

```python
from io import BytesIO      # bytes를 "메모리 속 가짜 파일"처럼 다루기 (업로드 CSV 읽을 때)
from pathlib import Path    # 경로를 Path("폴더") / "파일.csv" 처럼 / 로 이어 붙이기
import numpy as np
import pandas as pd

COLUMNS = ['날짜', '구분', '항목', '금액']   # 반드시 있어야 하는 컬럼 4개
MAX_ROWS = 5000                              # 최대 5,000행
MAX_AMOUNT = 1000000000000                   # 거래 1건당 최대 1조 원
MAX_FILE_BYTES = 5 * 1024 * 1024             # 업로드 파일 최대 5MB (= 5,242,880 bytes)
```

**상수(constant)란?**
- 프로그램 전체에서 **바뀌지 않는 기준값**. 관례상 **이름을 대문자**로 쓴다.
- 기준이 바뀌면 **여기 한 곳만** 고치면 아래 모든 함수에 반영된다.
  (5000을 코드 여기저기에 직접 쓰면 바꿀 때 하나쯤 꼭 빠뜨린다)

**왜 5MB가 5 × 1024 × 1024 일까?**
컴퓨터는 1000이 아니라 **1024 단위**로 센다. 1KB = 1024 bytes, 1MB = 1024KB.
그래서 십진수로 보면 약 5.24MB.

**천 단위 쉼표 출력** : `f"{MAX_AMOUNT:,}원"` → `1,000,000,000,000원`

## 2. 빈 표 만들기 : empty_records()

```python
def empty_records() -> pd.DataFrame:
    return pd.DataFrame({
        '날짜': pd.Series(dtype="string"),
        '구분': pd.Series(dtype="string"),
        '항목': pd.Series(dtype="string"),
        '금액': pd.Series(dtype="int64"),
    })
```

**왜 필요할까?**
- 그냥 `pd.DataFrame()` 은 컬럼도 자료형도 없는 **완전히 빈 표**.
- 그러면 나중에 `df['금액']` 으로 계산할 때 "그런 열 없음" 에러가 난다.
- 그래서 **행은 0개지만 컬럼 이름과 자료형은 정해진 "틀"** 을 만들어 둔다.

**`-> pd.DataFrame` 은 뭐지?** → **타입 힌트**. "이 함수는 DataFrame을 돌려줘요"라는 메모.
실행에는 아무 영향 없고, 코드를 읽는 사람을 위한 표시다.

## 3. 데이터 검증 : validate_records()

이 노트북의 **핵심 함수**. 하는 일은 세 가지.

1. 데이터가 규칙에 맞는지 하나씩 검사
2. 어긋나면 **`ValueError`를 발생**시켜 다음 단계로 못 넘어가게 막기
   → 잘못된 행을 몰래 지우지 않는다. 사용자가 **무엇이 틀렸는지 알고 직접 고치게**.
3. 통과하면 공백 제거·자료형 변환까지 마친 **깨끗한 표(clean)** 를 돌려주기

### 검증 규칙

| 검사 | 규칙 | 걸리는 예 |
|---|---|---|
| 중복 컬럼 | 같은 이름의 컬럼이 두 개면 안 됨 | `['금액', '금액']` |
| 필수 컬럼 | 날짜·구분·항목·금액이 모두 있어야 함 | '금액' 열 없음 |
| 행 수 | 최대 5,000행 | 5,001행 |
| 날짜 | `YYYY-MM-DD` 모양 + 실제 있는 날짜 + 1900~2100년 | `2026/01/05`, `2026-02-30` |
| 구분 | `수입` 또는 `지출` | `환불` |
| 항목 | 1~40글자 | 빈칸 |
| 금액 | 1원 ~ 1조 원 사이의 **정수** | `0`, `-500`, `1500.5`, `만원` |

**검사 순서 포인트** : **표 전체 모양(컬럼, 행 수) 먼저 → 각 칸의 값은 나중에.**
컬럼이 없으면 값 검사 자체를 할 수 없으니까 큰 문제부터 확인한다.

### 3-1. 표 모양 검사 (1~4단계)

```python
# 1) 중복 컬럼 : duplicated()는 "앞에서 이미 나온 이름인가?"를 True/False로
#    ['날짜', '금액', '금액'] → [False, False, True] → .any() → True
if frame.columns.duplicated().any():
    raise ValueError("동일한 컬럼 이름이 중복되었습니다.")

# 2) 필수 컬럼 : COLUMNS 중에서 frame에 "없는" 이름만 골라 리스트로
missing = [name for name in COLUMNS if name not in frame.columns]
if missing:   # 빈 리스트 [] 는 False → 다 있으면 통과
    raise ValueError("필수 컬럼이 없습니다: " + ", ".join(missing))   # ['항목','금액'] → "항목, 금액"

# 3) 행 수
if len(frame) > MAX_ROWS:
    raise ValueError(f"내역은 최대{MAX_ROWS:,}행까지 입력할 수 있습니다.")

# 4) 0행이면 더 검사할 게 없으니 빈 표 틀을 바로 반환 (return → 함수 끝)
if frame.empty:
    return empty_records()
```

### 3-2. 정리 (5~6단계)

```python
# 필수 4개 열만, 정해진 순서로 + 복사본 + 행 번호 0,1,2… 로 새로 매기기
clean = frame[COLUMNS].copy().reset_index(drop=True)

# 글자 열의 앞뒤 공백 제거 : " 월급 " → "월급"
for name in ["날짜", '구분', '항목']:
    clean[name] = clean[name].astype("string").str.strip()
```

- `.copy()` → 아래에서 값을 바꿔도 **원본은 그대로**.
- `reset_index(drop=True)` → 나중에 "**몇 번째 행**이 잘못됐는지" 알려주려면 번호가 순서대로여야 한다.
  `drop=True` 는 기존 인덱스를 새 열로 남기지 않고 버린다는 뜻.
- `.str` → "열 안의 문자열 **하나하나에** 적용해라".

### 3-3. 칸별 값 검사 (7단계) : 마스크 만들기

검사 결과를 **행마다 True(정상) / False(오류)** 를 담은 Series(= 마스크)로 만든다.
`valid_kind = [True, True, False]` → 3번째 행의 구분이 잘못됨.

**날짜 검사 : 세 조건을 모두 만족해야 True**

```python
date_text = clean["날짜"]
# 날짜로 변환. 변환 못 하는 값은 에러 대신 NaT(빈 날짜)로 → errors="coerce"
dates = pd.to_datetime(date_text, format="%Y-%m-%d", errors="coerce")

valid_dates = (
    date_text.str.fullmatch(r"\d{4}-\d{2}-\d{2}", na=False)   # ① 0000-00-00 모양인가?
    & dates.notna()                                           # ② 실제 있는 날짜인가?
    & dates.between("1900-01-01", "2100-12-31")               # ③ 허용 범위 안인가?
)
```

| 입력 | ① 모양 | ② 실제 날짜 | ③ 범위 | 결과 |
|---|---|---|---|---|
| `2026-01-05` | O | O | O | **True** |
| `2026-02-30` | O | X (2월 30일 없음) | - | False |
| `2026/03/10` | X (`/` 사용) | X | - | False |
| `날짜오류` | X | X | - | False |
| `1899-12-31` | O | O | X | False |

- `\d` = 숫자 한 글자, `{4}` = 4번 반복
- `fullmatch` = 문자열 **전체**가 이 모양이어야 함 (`2026-01-05abc` 는 False)
- `na=False` = 값이 비어 있으면 False

**구분 / 항목 검사**

```python
valid_kind = clean["구분"].isin(['수입', '지출'])            # 리스트 안에 있으면 True
valid_category = clean['항목'].notna() & clean["항목"].str.len().between(1, 40)
```

**금액 검사 : 4가지 모두 통과해야 True**

```python
raw_amount = clean['금액'].astype("string").str.strip()   # 3000000과 "12000"이 섞여 있으니 일단 글자로
amount = pd.to_numeric(raw_amount, errors="coerce")       # 숫자로. "만원" 같은 값은 NaN

valid_amount = (
    amount.notna()                    # ① 숫자로 바뀌었나?
    & np.isfinite(amount)             # ② 무한대(inf)가 아닌가? ("inf"도 숫자로 변환돼서 따로 막음)
    & amount.between(1, MAX_AMOUNT)   # ③ 1원 ~ 1조 원?
    & amount.mod(1).eq(0)             # ④ 정수인가? 1로 나눈 나머지가 0 (1500.5 → 0.5 → False)
).fillna(False)                       # 계산 중 생긴 빈 값은 "잘못된 값"으로 보고 False
```

### 3-4. 검사 결과 확인 → 에러 (8단계)

```python
for label, mask in [
    ("날짜: YYYY-MM-DD의 실제 날짜 (1900~2100년)", valid_dates),
    ("구분: 수입 또는 지출", valid_kind),
    ("항목: 1~40글자의 이름", valid_category),
    ("금액: 1원~1조원 양의 정수", valid_amount),
]:
    if not mask.all():   # 하나라도 False가 있으면
        rows = [str(i + 1) for i in clean.index[~mask][:10]]
        raise ValueError(f"{label}를 확인하세요. 잘못된 데이터 행: {', '.join(rows)}")
```

- 튜플 `(A, B)` 를 하나씩 꺼내서 `label = A`(에러 문구), `mask = B`(검사 결과)로 받는다.
  → 검사가 늘어나도 **리스트에 한 줄만 추가**하면 된다.
- 잘못된 행 번호 찾기를 한 단계씩 보면

| 코드 | 뜻 | 예 |
|---|---|---|
| `mask` | 검사 결과 | `[True, False, True, False]` |
| `~mask` | True/False 뒤집기 → **잘못된 행이 True** | `[False, True, False, True]` |
| `clean.index[~mask]` | 잘못된 행의 인덱스만 | `[1, 3]` |
| `[:10]` | 최대 10개까지만 | `[1, 3]` |
| `str(i + 1)` | 사람이 보기 편하게 **1부터** 세고 글자로 | `['2', '4']` |
| `', '.join(rows)` | 한 줄로 | `"2, 4"` |

### 3-5. 통과한 데이터 정리 (9단계)

```python
clean['날짜'] = dates.dt.strftime("%Y-%m-%d").astype("string")   # 날짜 → "2026-01-05" 글자로 통일
clean['금액'] = amount.astype("int64")                            # "12000" → 12000 정수로 확정
return clean
```

### 3-7. 테스트 : 잘못된 데이터 → **에러가 나야 성공**

```python
bad_examples = {
    "날짜 오류": pd.DataFrame([["2026/01/05", "수입", "월급", 1000]], columns=COLUMNS),
    "구분 오류": pd.DataFrame([["2026-01-05", "환불", "기타", 1000]], columns=COLUMNS),
    "금액 오류": pd.DataFrame([["2026-01-05", "지출", "식비", 0]], columns=COLUMNS),
}

for test_name, bad_df in bad_examples.items():
    try:
        validate_records(bad_df)
    except ValueError as e:
        print(f"[{test_name}] 검증 실패 확인: {e}")
```

출력 결과

```
[]
[날짜 오류] 검증 실패 확인: 날짜: YYYY-MM-DD의 실제 날짜 (1900~2100년)를 확인하세요. 잘못된 데이터 행: 1
[]
[구분 오류] 검증 실패 확인: 구분: 수입 또는 지출를 확인하세요. 잘못된 데이터 행: 1
[]
[금액 오류] 검증 실패 확인: 금액: 1원~1조원 양의 정수를 확인하세요. 잘못된 데이터 행: 1
```

- `[[ ... ]]` : 바깥 `[ ]` = 행 목록, 안쪽 `[ ]` = 한 행 → **1행짜리 표**
- `try / except` : 에러가 나도 프로그램이 멈추지 않고 `except` 로 와서 처리
- 에러가 **안 나면** 아무것도 출력되지 않음 → 그 검사가 제대로 구현 안 됐다는 뜻
- `[]` 가 찍히는 이유는 [10장](#10-헷갈렸던-것--주의할-점) 참고

## 4. 샘플 파일 읽기 : load_sample()

```python
def load_sample() -> pd.DataFrame:
    path = Path.cwd() / "data" / "sample_transactions.csv"   # (현재 폴더)/data/sample_transactions.csv
    if not path.exists():
        raise FileNotFoundError(
            f"샘플 파일을 찾을 수 없습니다. {path}\n"
            "data/sample_transactions.csv파일을 준비해 주세요"
        )
    return validate_records(pd.read_csv(path, encoding="utf-8-sig"))
```

- `Path.cwd()` : 노트북이 실행되는 **현재 폴더**
- 파일이 없으면 pandas의 어려운 에러 대신 **무엇을 해야 하는지 알려주는 에러**를 직접 낸다.
- 읽자마자 `validate_records()` 에 넣는다 → **파일에서 읽은 데이터도 같은 검사를 반드시 통과**.
- `encoding="utf-8-sig"` : 엑셀이 저장한 CSV 맨 앞의 BOM(보이지 않는 표시)을 자동 제거.

## 5. 업로드 CSV 읽기 : read_csv_bytes()

**왜 파일 경로가 아니라 bytes를 받을까?**
웹앱(Streamlit 등)에서 업로드된 파일은 디스크의 파일이 아니라 **파일 내용이 담긴 bytes**로 넘어오기 때문.

```python
def read_csv_bytes(content: bytes) -> pd.DataFrame:
    if len(content) > MAX_FILE_BYTES:                  # 1) 너무 크면 거절
        raise ValueError("CSV 파일은 최대 5MB까지 사용할 수 있습니다.")
    if not content:                                    # 2) 빈 파일 b"" 는 False
        raise ValueError("CSV 파일이 비어 있습니다.")

    for encoding in ["utf-8-sig", "cp949"]:            # 3) 인코딩 바꿔 가며 시도
        try:
            frame = pd.read_csv(BytesIO(content), encoding=encoding, nrows=MAX_ROWS + 1)
            return validate_records(frame)
        except UnicodeDecodeError:
            continue                                   # 글자 깨짐 → 다음 인코딩으로
        except (pd.errors.EmptyDataError, pd.errors.ParserError) as exc:
            raise ValueError("CSV 형식이 올바르지 않습니다. 쉼표 구분 파일을 사용하세요.") from exc
    raise ValueError("파일 인코딩을 읽을 수 없습니다. UTF-8또는 CP949 CSV로 저장하세요")
```

| 포인트 | 설명 |
|---|---|
| **인코딩** | 글자를 bytes로 저장하는 규칙. `utf-8-sig` = 요즘 표준 + 엑셀 BOM, `cp949` = 옛날 한글 윈도우/엑셀 |
| `BytesIO(content)` | bytes를 파일처럼 포장해서 `read_csv` 에 넘김 |
| `nrows=MAX_ROWS + 1` | 5,001행까지만 읽음 → 큰 파일을 다 읽지 않으면서도 "5,000행 초과"는 판단 가능 |
| `continue` | 이번 반복은 건너뛰고 다음 반복으로 |
| `raise ... from exc` | pandas 에러를 쉬운 메시지로 바꾸되, **원래 에러도 함께 기록** (디버깅용) |
| 마지막 `raise` | for문을 끝까지 돌았다 = **두 인코딩 모두 실패** |

테스트는 `sample.to_csv(index=False).encode("utf-8-sig")` 로 **표 → CSV 글자 → bytes** 를 만들어서 업로드 파일처럼 넣어 봤다.

## 6. 파생 변수 : add_features()

**파생 변수** = 원래 있던 열을 가공해서 새로 만든 열.

```python
def add_features(frame: pd.DataFrame, threshold: int = 100000) -> pd.DataFrame:
    result = frame.copy()

    # [월] "2026-01-05" → "2026-01"
    result["월"] = result["날짜"].apply(lambda d: d[:7])

    # [표시] 수입 / 큰 지출 / 일반 지출
    result["표시"] = result.apply(
        lambda row: "수입" if row["구분"] == "수입"
        else ("큰 지출" if row["금액"] >= threshold else "일반 지출"),
        axis=1,
    ) if len(result) else pd.Serise(dtype="string")   # ⚠ 오타 : pd.Series
    return result
```

- **기본값 매개변수** `threshold: int = 100000`
  - `add_features(clean)` → 기준 10만 원
  - `add_features(clean, threshold=50000)` → 기준 5만 원
- `lambda d: d[:7]` : 이름 없는 짧은 함수. 문자열 앞 7글자.
- `Series.apply(함수)` → **값 하나씩**, `DataFrame.apply(함수, axis=1)` → **행 하나씩** (`row["구분"]`, `row["금액"]` 처럼 여러 열을 함께 볼 수 있음)
- **조건 표현식** `A if 조건 else B` : 조건이 참이면 A, 거짓이면 B. 중첩하면

```
구분 == 수입?  ── 예 → "수입"
              └ 아니오 → 금액 >= 기준?  ── 예 → "큰 지출"
                                       └ 아니오 → "일반 지출"
```

- 맨 끝 `if len(result) else ...` : 빈 표에 `apply` 를 쓰면 열이 아니라 표가 나와서, 데이터가 있을 때만 실행.

## 7. 요약 : summarize()

반환값이 **두 개** : ① 항목별 지출 합계 ② 월별 요약

```python
def summarize(frame: pd.DataFrame) -> tuple[pd.DataFrame, pd.DataFrame]:
    expenses = frame[frame["구분"] == "지출"]          # 지출만 (불리언 마스크)

    categories = (
        expenses.groupby("항목")["금액"].sum()          # 항목별 합계
        .sort_values(ascending=False)                   # 큰 금액부터
        .rename("지출 합계")                            # 열 이름이 될 이름
        .reset_index()                                  # Series → DataFrame
    )

    monthly = frame.pivot_table(index="월", columns="구분", values="금액",
                                aggfunc="sum", fill_value=0)
    monthly = monthly.reindex(columns=["수입", "지출"], fill_value=0)

    monthly["남은 금액"] = monthly["수입"] - monthly["지출"]
    monthly["남은 비율(%)"] = (monthly["남은 금액"] / monthly["수입"].replace(0, np.nan) * 100).round(1)

    return categories, monthly.reset_index()
```

**피벗 테이블 결과 모양**

```
구분      수입      지출     남은 금액   남은 비율(%)
월
2026-01  3000000   12000    2988000     99.6
2026-02  3000000   50000    2950000     98.3
```

| 포인트 | 왜? |
|---|---|
| 바깥 `( )` 로 감싸기 | 여러 줄에 걸쳐 메서드를 이어 쓰기 (메서드 체이닝) |
| `reindex(columns=["수입","지출"], fill_value=0)` | 지출이 한 번도 없으면 '지출' 열 자체가 안 생김 → 없는 열을 0으로 만들어서 `수입 - 지출` 계산 에러 방지 |
| `.replace(0, np.nan)` | 수입이 0원인 달은 0으로 나누게 됨 → inf(무한대) 대신 NaN(값 없음)이 나오게 |
| `return a, b` → `x, y = summarize(...)` | 두 개를 튜플로 돌려주고, **튜플 언패킹**으로 각각 받기 |

## 8. CSV 내보내기 : csv_bytes()

하는 일 두 가지 : **① 보안 처리(CSV 인젝션 방지)** ② **엑셀 한글 깨짐 방지**

```python
def csv_bytes(frame: pd.DataFrame) -> bytes:
    safe = frame.copy()
    for name in safe.select_dtypes(include=['object', 'string']).columns:   # 글자 열만
        safe[name] = safe[name].map(
            lambda value: "'" + value
            if isinstance(value, str) and value.lstrip().startswith(("=", '+', '-', '@', '\t', '\r'))
            else value
        )
    return safe.to_csv(index=False, na_rep='', encoding=None).encode("utf-8-sig")
```

**CSV 인젝션이란?**
엑셀은 `=`, `+`, `-`, `@` 로 시작하는 칸을 글자가 아니라 **수식으로 실행**한다.
악의적인 수식이 들어 있으면 위험하니까, 앞에 작은따옴표 `'` 를 붙여 **그냥 글자**로 만든다.

```
"=1+1"  →  "'=1+1"    (엑셀에서는 =1+1 이라는 글자로 보임)
"식비"  →  "식비"      (그대로)
```

**to_csv 옵션**

| 옵션 | 뜻 |
|---|---|
| `index=False` | 행 번호는 CSV에 안 넣음 |
| `na_rep=''` | 빈 값(NaN)은 "nan" 대신 빈칸 |
| `encoding=None` | 경로 없이 호출 → CSV 내용을 **문자열로 반환** |
| `.encode("utf-8-sig")` | 문자열 → bytes. 맨 앞에 BOM이 붙어서 **엑셀이 한글을 제대로 읽음** |

**출력된 바이트 읽는 법**

```
b'\xef\xbb\xbf             → UTF-8 BOM
\xeb\x82\xa0\xec\xa7\x9c   → '날짜' (한글 한 글자 = UTF-8에서 3바이트)
```

결과는 **메모리 속 bytes** → `Path("파일.csv").write_bytes(...)` 로 파일 저장도, Streamlit 다운로드 버튼에 넘기기도 가능.

## 10. 헷갈렸던 것 / 주의할 점

### 10-1. 출력에 `[]` 가 왜 찍히지?

`validate_records()` 안에 **디버깅용 `print(missing)`** 이 남아 있어서.
테스트 데이터는 모두 `columns=COLUMNS` 로 만들어서 빠진 컬럼이 없음 → `missing = []` → `[]` 출력.
함수를 부를 때마다 한 번씩 찍힌다. **확인이 끝난 디버깅 print는 지우거나 주석 처리하기.**

### 10-2. 에러 메시지 문장은 누가 정한 거지?

**전부 내가 코드에 쓴 것.** 파이썬이 정하는 건 `ValueError` 라는 **에러 종류 이름**과 Traceback 형식뿐이다.

```
[구분 오류] 검증 실패 확인: 구분: 수입 또는 지출를 확인하세요. 잘못된 데이터 행: 1
└test_name┘ └─ print 문구 ─┘ └──── label ────┘└──────── raise 문구 ────────┘
```

| 조각 | 나온 곳 |
|---|---|
| `[구분 오류]` | 테스트 셀 `bad_examples` 의 키 |
| `검증 실패 확인:` | 테스트 셀 `print(f"[{test_name}] 검증 실패 확인: {e}")` |
| `구분: 수입 또는 지출` | `validate_records()` for문 리스트의 `label` |
| `를 확인하세요. 잘못된 데이터 행: 1` | `raise ValueError(f"{label}를 확인하세요. ...")` |

`raise` 할 때 넣은 문장이 `except ValueError as e:` 의 **`e` 에 담겨** 출력된다.

### 10-3. "지출를" 이 어색한 이유

`를` 이 고정이라서. label이 받침으로 끝나면 `을` 이 맞다. 조사가 필요 없게 바꾸면 깔끔하다.

```python
raise ValueError(f"[{label}] 형식을 확인하세요. 잘못된 데이터 행: {', '.join(rows)}")
```

### 10-4. `pd.Serise` 오타

`add_features()` 의 `pd.Serise` → **`pd.Series`** 가 맞다.
지금은 빈 표가 안 들어와서 실행되지 않을 뿐, 빈 표가 오면 `AttributeError`.
→ **에러가 안 난다고 코드가 맞는 건 아니다.** 그 줄이 실행되지 않았을 수도 있다.

### 10-5. `and` 대신 `&` 를 쓰는 이유

Series끼리는 **행마다 따로** 비교해야 해서 `&`(그리고), `|`(또는), `~`(아니다)를 쓴다.
`and` 를 쓰면 "Series 전체가 참이냐?"를 물어보게 돼서 에러가 난다.
조건마다 **괄호**로 감싸는 것도 잊지 말기.

### 10-6. `errors="coerce"`

`pd.to_datetime`, `pd.to_numeric` 에서 변환할 수 없는 값을 **에러 대신 빈 값(NaT / NaN)** 으로 바꾼다.
→ 일단 전부 변환해 놓고, 빈 값인지(`notna()`)로 오류를 한꺼번에 찾는 패턴.

### 10-7. `.copy()` 를 계속 쓰는 이유

함수 안에서 받은 표를 바로 고치면 **함수 밖의 원본까지 바뀔 수 있다.**
복사본에서 작업하면 원본은 안전하다.
